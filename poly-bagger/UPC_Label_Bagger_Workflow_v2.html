UPC Label → Poly Bagger Printer Workflow

Source: .docx → ZPL → Zebra ZTC 110Xi4-203dpi ZPL (203 DPI thermal transfer)
Date: 2026-07-24

Verified AKV PLUM label: barcode 51655106437. The printer’s 180° image version printed upside down, so use the original artwork with explicit normal ZPL orientation (^PON and ^FWN). Test job Zebra-53 completed.

The Workflow (macOS)

Step 1: Extract the label from the .docx

AKV PLUM: Keep the source artwork as-is. The printer was applying the wrong orientation to the rotated image, so the ZPL below explicitly sets normal print and field orientation.

First install Pillow (one time):

pip3 install Pillow

Create a file called step1_extract.py with this content:

step1_extract.py
from zipfile import ZipFile
from pathlib import Path
from PIL import Image

source = Path("UPC Labels/AKV PLUM - PSA RETAIL.docx")
output = Path("UPC Labels/AKV_PLUM_PSA_RETAIL_upright.png")

with ZipFile(source) as z:
    image_name = next(name for name in z.namelist() if name.startswith("word/media/"))
    with z.open(image_name) as f:
        image = Image.open(f).convert("RGB")

image.save(output)
print(f"Saved {output}")

Run it:

python3 step1_extract.py

Run it from the project folder. Result: creates UPC Labels/AKV_PLUM_PSA_RETAIL_upright.png.

Step 2: Scale and generate ZPL

Create a file called step2_generate_zpl.py. This version reads the original PLUM artwork and writes normal-orientation ZPL beside it. Change scale = 4 to 3, 4, or 5 if needed.

step2_generate_zpl.py
from PIL import Image
from pathlib import Path

scale = 4
input_path = Path("UPC Labels/AKV_PLUM_PSA_RETAIL_upright.png")
output_path = Path("UPC Labels/AKV_PLUM_PSA_RETAIL_normal.zpl")
img = Image.open(input_path).convert("1")
w, h = img.size
img = img.resize((w * scale, h * scale), Image.NEAREST)
w, h = img.size

bytes_per_row = (w + 7) // 8
pixels = list(img.getdata())
hex_rows = []
for y in range(h):
    row_bytes = []
    for byte_idx in range(bytes_per_row):
        byte_val = 0
        for bit_idx in range(8):
            px_idx = y * w + byte_idx * 8 + bit_idx
            if px_idx < y * w + w:
                px = pixels[px_idx]
                bit = 0 if px else 1
                byte_val = (byte_val << 1) | bit
            else:
                byte_val <<= 1
        row_bytes.append(byte_val)
    hex_rows.append("".join(f"{b:02X}" for b in row_bytes))
hex_str = "".join(hex_rows)
total_bytes = bytes_per_row * h

# --- PADDING SETTINGS ---
# Adjust these if the label is cut off or has too much whitespace:
bottom_padding = 80
side_padding   = 120
top_margin     = 30
left_margin    = 60

label_h = h + bottom_padding
label_w = w + side_padding

zpl = f"^XA\n^PON\n^FWN\n^LL{label_h}\n^PW{label_w}\n^LS0\n^FO{left_margin},{top_margin}^GFA,{total_bytes},{total_bytes},{bytes_per_row},{hex_str}^FS\n^XZ"

with open(output_path, "w") as f:
    f.write(zpl)

print(f"Saved {output_path}  ({w}x{h} dots = {w/203:.2f}\" x {h/203:.2f}\" at 203 DPI)")
print(f"Label area: {label_w}x{label_h} dots with padding")

Run it:

python3 step2_generate_zpl.py

Result: creates UPC Labels/AKV_PLUM_PSA_RETAIL_normal.zpl.

Step 3: Connect printer via USB

USB-B to USB-A cable (or USB-C adapter). Port is on the back of the printer.

Step 4: Check the printer is detected

In Terminal, run:

lpinfo -v | grep -i zebra

Expected output:

direct usb://Zebra%20Technologies/ZTC%20110Xi4-203dpi%20ZPL?serial=JJL100932

Step 5: Create a raw print queue (one-time)

In Terminal, run:

lpadmin -p Zebra -E \
  -v "usb://Zebra%20Technologies/ZTC%20110Xi4-203dpi%20ZPL?serial=JJL100932" \
  -o printer-is-shared=false

No output means it worked.

Step 6: Send the ZPL file

IMPORTANT: The -o raw flag is critical. Without it, macOS converts the ZPL to a raster image (garbled output).

In Terminal, run:

lp -d Zebra -o raw "UPC Labels/AKV_PLUM_PSA_RETAIL_normal.zpl"

Step 7: Verify

lpq -P Zebra

Shows: "Zebra is ready / no entries"

Step 8: Adjust size (if needed)

Open step2_generate_zpl.py, change the padding values, re-run, re-send:

bottom_padding = 80    # increase if bottom is cut off
side_padding   = 120   # increase if sides are cut off
top_margin     = 30    # increase to push image down
left_margin    = 60    # increase to push image right

Then:

python3 step2_generate_zpl.py
lp -d Zebra -o raw "UPC Labels/AKV_PLUM_PSA_RETAIL_normal.zpl"

ZPL Commands Explained

CommandPurpose
^XA / ^XZStart / end of label format
^LLnnnLabel length in dots (prevents bottom cutoff)
^PWnnnPrint width in dots
^LS0Label shift (0 = no shift)
^FOx,yField origin (position from top-left in dots)
^GFA,...Graphic field (ASCII hex monochrome image)
^FSEnd of field

Windows (No Admin Rights)

If the printer appears under Ports (COM & LPT) in Device Manager:

mode COM4:9600,n,8,1
copy /b "UPC Labels\AKV_PLUM_PSA_RETAIL_normal.zpl" COM4:

Replace COM4 with your actual COM port number.

Zebra Setup Utilities (Windows, Admin Required)

Official free Zebra tool for sending ZPL files and configuring printers.

Download: Zebra Printer Setup Utilities (official page) — also available on the iOS App Store and Google Play.

  1. Download and install (requires admin rights)
  2. Open → printer should auto-detect
  3. Click "Send File" tab → browse to AKV_PLUM_PSA_RETAIL_normal.zpl → Send

Driver needed: Zebra ZT-10Xi4 (203 dpi) ZPL driver — use the ZPL driver, not the "Designer" driver (which converts to images instead of sending raw ZPL).

LabelView (TEKLYNX, Windows, Licensed)

LabelView is the industry-standard label-design software used with Advanced Poly T-1000 baggers. It is a licensed Windows-only application from TEKLYNX and creates .nlbl files.

Note: LabelView is not free — you need a license from TEKLYNX or Advanced Poly. It typically ships with the T-1000 bagger or is available through your Advanced Poly sales rep.

  1. Open LabelView on a Windows machine
  2. Import AKV_PLUM_PSA_RETAIL_upright.png as a reference image
  3. Rebuild the label layout from scratch in LabelView (set label dimensions, add barcode as a proper barcode object, add text fields)
  4. Save as .nlbl
  5. Send to printer via LabelView's built-in print function
  6. On the T-1000 touchscreen: Printer → Stored Labels → Load the saved label

Important: You cannot convert ZPL or PNG into LabelView's .nlbl format. You must recreate the label inside LabelView using the PNG as a visual reference.

Linux / Unix Systems

Same approach as macOS — use CUPS (lp) to send raw ZPL:

# One-time: add raw queue
lpadmin -p Zebra -E -v "usb://Zebra%20Technologies/ZTC%20110Xi4-203dpi%20ZPL?serial=JJL100932" -o printer-is-shared=false

# Send ZPL (raw flag required)
lp -d Zebra -o raw "UPC Labels/AKV_PLUM_PSA_RETAIL_normal.zpl"

Or send directly over the network if the printer has an IP:

nc printer-ip 9100 < "UPC Labels/AKV_PLUM_PSA_RETAIL_normal.zpl"

Zebra printers listen on TCP port 9100 (raw printing). This works on any OS without any driver.

Troubleshooting

IssueFix
Garbled textForgot -o raw. macOS converted the ZPL.
Nothing happensCheck USB, verify queue (lpstat -p Zebra), check printer screen.
Bottom cut offIncrease bottom_padding in step2_generate_zpl.py, re-run, re-send.
Sides cut offIncrease side_padding or left_margin, re-run, re-send.
Too much whitespaceDecrease padding values, re-run, re-send.
Label too small/bigChange scale in step2_generate_zpl.py, re-run, re-send.
Not detected on MacTry different cable, port, or check System Information > USB.
Not detected on WindowsCheck Device Manager category to determine the fix.
