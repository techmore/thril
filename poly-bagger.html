Getting started

Initial setup & Mac configuration

One-time printer setup for macOS: connect the Zebra printer, create the CUPS queue, and install dependencies. This is the only section that requires admin access.

Connect printer

Connect the Zebra ZTC 110Xi4-203dpi printer via USB-B to USB-A cable (or USB-C adapter). The port is on the back of the printer.

Create CUPS print queue (one-time)

Run this once to register the printer queue on macOS. You only need to do this when first connecting the printer:

lpadmin -p Zebra -E \ -v "usb://Zebra%20Technologies/ZTC%20110Xi4-203dpi%20ZPL?serial=JJL100932" \ -o printer-is-shared=false

Verify detection

Confirm the printer is visible to the system:

lpinfo -v | grep -i zebra

Install dependencies

The Python label script requires Pillow for image processing:

pip3 install Pillow

Critical: always use -o raw

Without -o raw, macOS converts the ZPL to a raster image, producing garbled output. Always pass -o raw when sending ZPL via lp.
The one-step script (print_label.py) handles -o raw automatically. You only need to worry about this when sending ZPL files directly.

Daily operation

Usage & workflow

Print UPC barcode labels from .docx source files using the one-step Python script or the manual ZPL workflow.

One-step automated script

From the poly-bagger/ directory, run print_label.py to extract the image, generate ZPL, and print in one command:

python3 print_label.py "UPC Labels/AKV PLUM - PSA RETAIL.docx"

If the label prints upside down, add --rotate 180:

python3 print_label.py "UPC Labels/AK47 G2 Ribbed PLUM - PSA RETAIL.docx" --rotate 180

Script options

FlagDefaultDescription
--scale4Scale factor: 3 (2.85"), 4 (3.80"), 5 (4.75")
--rotate0Rotate image degrees (180 to fix upside down)
--no-printoffGenerate ZPL only, don't send to printer

Manual workflow

If you need to inspect or modify the intermediate files:

  1. Extract image from .docx: python3 -c "..."
  2. Rotate if needed: python3 -c "Image.open(...).rotate(180).save(...)"
  3. Generate ZPL: encode 1-bit image as ^GFA hex
  4. Send to printer: lp -d Zebra -o raw label.zpl
  5. Verify queue: lpq -P Zebra

Printer queue commands

CommandPurpose
lpq -P ZebraCheck print queue
lpstat -p ZebraCheck printer status
cancel -a ZebraCancel all queued jobs
cupsenable ZebraRe-enable printer (if disabled)

Infrastructure

Compressor & air supply setup

The T-1000 bagger uses compressed air for bag-opening jets and film sealing. Proper air supply is critical for consistent operation.

Compressor requirements

ParameterRequirementNotes
Minimum pressure80 PSIRegulated at the machine inlet
Recommended flow6–10 CFM @ 90 PSIHigher CFM reduces cycle-time lag
Air line fitting1/4" NPT quick-disconnectStandard industrial coupler
Air hose3/8" ID minimum1/4" ID causes pressure drop on long runs
Filter / dryerWater separator + coalescing filterMoisture causes seal failures

Connection & startup

  1. Ensure compressor tank is drained of condensate (open petcock until dry)
  2. Verify regulator is set to 80–90 PSI at the machine inlet
  3. Connect air hose to the T-1000 quick-disconnect on the rear panel
  4. Open the compressor ball valve — listen for air flow
  5. Cycle the bagger once manually to purge any moisture from the lines
  6. Check the pressure gauge on the machine — should hold steady during a cycle

Daily operator checks

  1. Drain compressor tank (moisture accumulates overnight)
  2. Check regulator pressure — adjust if below 80 PSI at idle
  3. Inspect air hose for kinks, cuts, or loose fittings
  4. Listen for air leaks while machine is idle — hissing indicates a leak
  5. Verify the water separator bowl isn't full — drain if needed
Low air pressure is the most common cause of poor seals, misaligned bags, and inconsistent label placement. Always check the regulator pressure first when troubleshooting bag quality issues.

Quality

Rebagging procedure

When a product needs to be removed from its original bag and placed into a new one due to damage, incorrect labeling, or QC failure.

When to re-bag

SituationAction
Bag torn or punctured during handlingRe-bag with the same label on a fresh bag
Label printed crooked or off-centerRe-bag with a corrected label print
Seal failed (bag not closed)Re-bag; inspect sealer bar for residue or damage
Wrong product in bagRe-bag with correct product and label
QC inspection failureRepair/rework per NCR, then re-bag with original label if product passes
Film roll change caused misaligned printRe-bag any products bagged during the transition

Step-by-step re-bagging

  1. Inspect the product — ensure it isn't damaged and still meets QC criteria
  2. Remove old bag — cut or tear open the original bag; discard it
  3. Verify the label — confirm the existing label is correct and legible, or print a new one
  4. Place product in new bag — align the product so the label faces outward and is readable
  5. Position the label — ensure the barcode is not wrinkled, folded, or obscured
  6. Seal the bag — run through the T-1000 sealer or use a hand sealer if doing a single bag
  7. Verify the seal — tug test on both ends of the seal; no gaps
  8. QC check — confirm the barcode scans, label is upright, bag is clean

Label reuse rules

  1. If the original label is undamaged and still adhered, it can be reused on the new bag
  2. If the label lifted or is creased, print a fresh label using print_label.py
  3. Never hand-write a replacement barcode — always print from the .docx source
  4. Re-bagged items must be logged in the rework log (form REWORK-001)

Support

Troubleshooting: label placement & orientation

Label position on the bag can vary due to printer calibration, media alignment, padding values, or orientation. Use this guide to isolate and correct placement issues.

Placement variance: root causes & fixes

SymptomRoot causeFix
Label shifted too far left left_margin too low Increase left_margin (default 60) in generate_zpl() — try 80–120
Label shifted too far right left_margin too high or ^FO X too large Decrease left_margin (try 40–20) or reduce side_padding
Label too high (near top of bag) top_margin too low Increase top_margin (default 30) — try 50–80
Label too low (near bottom of bag) top_margin too high or bottom_padding too low Decrease top_margin (try 10–20) or increase bottom_padding
Label prints upside down on bag Image not rotated 180° Add --rotate 180 to the script, or rotate the image in Python before ZPL generation
Label prints mirrored / reversed Wrong bit ordering in ^GFA Use byte_val = (byte_val << 1) | bit with bit = 0 if px else 1. First pixel = MSB = leftmost dot. Do not reverse bits.
Bottom of label cut off bottom_padding too low Increase bottom_padding (default 80) — try 120–160
Sides of label cut off side_padding too low Increase side_padding (default 120) — try 160–200
Label prints too large for bag Scale factor too large Reduce --scale from 4 to 3 (2.85" width)
Label prints too small to read Scale factor too small Increase --scale from 4 to 5 (4.75" width)
Printer shows "not ready" / rejects job Bad ZPL with ^PON/^FWN Remove those commands. Reboot printer (power cycle). CUPS re-enable won't fix it.
Garbled / unreadable printout Wrong bit ordering or missing -o raw Check bit ordering in ^GFA. Confirm you're sending with -o raw (or use print_label.py).

Padding values reference

All adjustments are in dots at 203 DPI. Modify these in print_label.py (inside generate_zpl()):

ParameterDefaultEffect
left_margin60Shifts label left/right
top_margin30Shifts label up/down
bottom_padding80Extra space below image (prevents clipping)
side_padding120Total side padding (prevents side clipping)

Mac-specific orientation setup

On macOS, the printer driver and CUPS filters can interfere with raw ZPL passthrough. This setup ensures correct orientation:

  1. Create the print queue with lpadmin as shown above — use the raw USB URI, do not install a macOS printer driver
  2. Always send ZPL with -o raw to bypass macOS rasterization
  3. If the label orientation is wrong, fix it in Python with --rotate 180 — never use ZPL orientation commands
  4. The print_label.py script handles all of this automatically: raw queue, correct bit ordering, rotation in Python
After a bad ZPL job: The printer may show "not ready" persistently. Power-cycle the printer (unplug → wait 10s → plug back in). Do not rely on CUPS commands to clear this state.
Still having issues? Check the compressor pressure (should be 80+ PSI), verify the film roll is seated correctly, and ensure the label media matches the printer DPI setting (203 DPI).
